Glossary

The vocabulary of the course, collected in one place and sorted alphabetically. Every entry is tagged with the week in which you first meet it, and with that week’s block, so you can still read this page in the same order as the Schedule if you want to. Terms inside a definition link to their own entries, and software entries link to their official documentation. The page grows with the course: a term is added in the week it is taught.

Nothing here replaces the slides. A glossary entry is the short version you can check quickly, not the explanation.

Tip

Use this page as a lookup. If a term on a slide or in a homework is unfamiliar, search this page first. If it is missing, say so in class, because the gap is probably not only yours.

A

Aesthetic mapping
The link between a variable and a visual property of a plot, such as position, colour, size or shape, written inside aes(). Inside aes() a property follows the data, outside it is one fixed value for every mark. Documentation: ggplot2: aesthetic mappings Week 5 Scientific programming fundamentals data r
Annotation
Marks added to a figure that are not rows of the data, such as a text note, a reference line or a label on a single point. Annotate the few things the reader should notice, not everything, so the annotation carries information instead of clutter. See also: Data-ink ratio. Week 5 Scientific programming fundamentals data interpretation
Array and tensor
The generalisation of a matrix to three or more dimensions, created in R with array(). In mathematics it is called a tensor and written in calligraphic as \(\mathcal{X}\), and this course rarely needs one. Documentation: R documentation: arrays Week 3 Scientific programming fundamentals r data
Assignment
Storing a value in an object under a name with <-, read aloud as “gets”: country <- "Germany". Assigning to a name that already exists overwrites it without asking. Documentation: R documentation: assignment operators Week 3 Scientific programming fundamentals r

B

Bar chart
A chart that shows a value per category by the length of a bar, either a count of rows or a value computed beforehand. Because length carries the value, bars start at zero, and their order is a decision, set through the levels of a factor. See also: Truncated axis. Week 5 Scientific programming fundamentals data
Base R
The functions R ships with before any package is installed, such as mean(), round() and data.frame(). Everything in week 3 was base R. Documentation: R documentation: the base package Week 4 Scientific programming fundamentals r
Box plot
A compact summary of a numeric variable, often one box per group: the line marks the median, the box holds the middle half of the observations, and whiskers and points show the rest. With few observations, draw the points themselves on top, because a box hides how many there are. See also: Violin plot, Jitter. Week 5 Scientific programming fundamentals data

C

Caption
The descriptive text attached to a figure or a table, written in the Markdown or set with the fig-cap and tbl-cap cell options. A good caption lets a reader understand the figure or table without the surrounding text. Documentation: Quarto: figures Week 2 Scientific programming fundamentals quarto
Case sensitivity
R treats upper and lower case as different, so city and City are two different names and Mean() is not mean(). A wrong capital letter is the most common cause of an “object not found” error. Week 3 Scientific programming fundamentals r
Cell option
A #| line at the top of a code cell that controls it, such as label:, echo: false (hide the code), eval: false (do not run it), include: false (show nothing) or error: true (show the error and keep rendering). Set under execute: in the YAML header, an option applies to every cell instead. Documentation: Quarto: execution options Week 3 Scientific programming fundamentals quarto
Character
R’s type for text, also called a string, always written in quotes: "Germany". A number in quotes is text, so "42" + 1 is an error until it is converted. Documentation: R documentation: character vectors Week 3 Scientific programming fundamentals r data
Chartjunk
Tufte’s word for decoration in a figure that carries no information and distracts from the data: 3D effects, heavy borders, gradients, ornamental grids (Tufte 1983). It lowers the data-ink ratio and often distorts what the reader perceives. See also: Graphical perception. Week 5 Scientific programming fundamentals data interpretation
Choropleth
A map that colours each area, such as a country, by the value of a variable. The values usually arrive through a join by name, so an area without a match shows up empty, which looks like missing data but may be a spelling difference. See also: Simple features. Week 5 Scientific programming fundamentals data
Clone
Making a local copy of a remote repository, including its full history. It is how a homework repository gets from GitHub onto your computer. Documentation: Git: git clone Week 2 Scientific programming fundamentals git
Code cell
A block of executable code inside a .qmd, also called a code chunk, which starts with three backticks and {r} and ends with three backticks. Quarto runs it on render and places the result directly underneath, and every cell in this course carries a label. See also: Cell option, Inline code. Documentation: Quarto: computations Week 2 Scientific programming fundamentals quarto r
Codebook
The documentation of a dataset, listing every variable with what it measures, its scale or categories, and how missing values are coded. Read it before analysing, because column names rarely say enough. Week 4 Scientific programming fundamentals data
Coercion
R changing values from one type to another automatically, most often when a vector mixes types, without anyone asking for it. c(1, 2, "three") becomes all text and c(1, TRUE, FALSE) becomes the numbers 1, 1 and 0, whereas type conversion is the same change made on purpose. Week 3 Scientific programming fundamentals r data
Colour palette
The set of colours a figure uses for a variable, matched to its kind: qualitative for categories without an order, sequential for values from low to high, diverging for values above and below a meaningful midpoint. Avoid letting red against green carry a distinction, and prefer palettes such as viridis that stay distinct for colourblind readers and in greyscale. See also: Redundant encoding. Documentation: ggplot2: viridis colour scales Week 5 Scientific programming fundamentals data
Column type
The data type of a column, shown in short form when a tibble is printed: <chr> character, <dbl> double, <int> integer, <lgl> logical, <fct> factor and <date> date. Check it first with new data, because a number or a date read in as text breaks everything that follows. Documentation: tibble: column types Week 4 Scientific programming fundamentals r data
Comment
Text after a # on a line of code, which R ignores when it runs the code. In a Quarto document the prose carries the reasoning, so comments stay short and say why a line is there. Documentation: R Language Definition: comments Week 3 Scientific programming fundamentals r
Commit
One recorded snapshot of the project: the staged changes, who made them, when, and a message saying what changed. A commit is the unit of history, so it should be a meaningful checkpoint. See also: Commit history. Documentation: Git: git commit Week 2 Scientific programming fundamentals git
Commit history
The list of all commits in a repository, newest first, each with its message, author and date, shown by git log or in Positron’s Source Control view. It is the record of how the project developed, and the way back to any earlier version. Documentation: Pro Git: viewing the commit history Week 2 Scientific programming fundamentals git
Commit message
The short text attached to a commit, written for a future reader, most importantly future you. “Add figure and cross-reference to introduction” helps, “Update” does not, and it is also where AI assistance gets declared. Week 2 Scientific programming fundamentals git workflow
Comparison and logical operators
Operators that return TRUE or FALSE: <, >, ==, !=, %in%, combined with & (and), | (or) and ! (not). Note that = assigns and == compares. Documentation: R documentation: relational operators Week 3 Scientific programming fundamentals r
Console
The interactive R session in Positron, where code runs line by line and prints its result straight away. Use it to try things out and for one-off commands such as install.packages(), and keep everything that belongs to the analysis in the document. See also: Fresh R session. Week 2 Scientific programming fundamentals r workflow
CRAN
The Comprehensive R Archive Network, a network of servers around the world that store identical, up-to-date versions of R and of more than 20,000 contributed packages. install.packages() downloads from it. Documentation: CRAN Week 4 Scientific programming fundamentals r
Cross-reference
A numbered, clickable reference from the text to a labelled figure, table, equation or section, written as @fig-example. A label survives reordering, and a phrase such as “the figure below” does not. Documentation: Quarto: cross-references Week 2 Scientific programming fundamentals quarto
CSV
Comma-separated values: a plain-text file with one row per line and the columns separated by commas, which any program can read. Files saved by a German-language Excel often separate columns with semicolons instead, and readr reads those with read_csv2(). Documentation: readr Week 4 Scientific programming fundamentals data

D

Data cycle
The stages of a data analysis: import the data, tidy it, transform it, visualise it, model it, and communicate the result. In a real project the middle stages loop, because a plot or a model often sends you back to tidy or transform again. Documentation: R for Data Science: introduction Week 4 Scientific programming fundamentals workflow data
Data frame and tibble
R’s structure for a rectangular dataset: a table in which each column is a vector with its own type, so one dataset can mix numbers, text and logicals. A tibble is the tidyverse’s modern reimagining of the data frame, with friendlier printing and fewer surprises. See also: Tidy data, Column type. Documentation: R documentation: data frames Week 3 Scientific programming fundamentals data r
Data structure
How R organises values: from a single value, through vectors, matrices and arrays, to data frames and lists. Each step adds a dimension or, for data frames and lists, the freedom to mix types. See also: Scalar, Vector, Matrix, Array and tensor, Data frame and tibble, List. Week 3 Scientific programming fundamentals r data
Data summary
Step 2 of the eight-step workflow: describing the data an analysis uses, its variables, measurement, coverage and obvious issues, before any model. In practice it is a pipeline ending in a captioned table, and every decision that changes the data, such as dropping missing values, is named in the text. Week 4 Scientific programming fundamentals workflow data
Data type
What kind of information a value is: double, integer, character or logical, plus factor and Date built on top of them. class() tells you which one you have. See also: Double and integer, Character, Logical, Factor, Date, Column type. Documentation: R Language Definition: basic types Week 3 Scientific programming fundamentals r data
Data-ink ratio
Edward Tufte’s measure of a figure: the share of its ink that shows data rather than decoration (Tufte 1983). Raising it means removing every mark that carries no information, such as heavy grids, backgrounds and redundant legends, and choosing deliberately what stays. See also: Chartjunk. Week 5 Scientific programming fundamentals data interpretation
Date
R’s type for calendar dates, created from text in the form year-month-day, as in as.Date("1957-03-25"). A date knows about the calendar, so dates can be sorted and subtracted. Documentation: R documentation: dates Week 3 Scientific programming fundamentals r data
Default argument value
The value an argument takes when the call does not supply one, set in the function definition, as digits = 0 is for round(). It is why many functions work with a single argument, and the Usage section of a help page lists every default. Week 3 Scientific programming fundamentals r
Density plot
A smooth curve estimated from the data that shows the shape of a numeric variable, an alternative to the histogram without bins. The area under the curve is 1, so its height is a probability density, not a count. Week 5 Scientific programming fundamentals data probability
Diff
A comparison of two versions of a file, showing what was removed, what was added and where. Reading the diff before you commit is how you check that a commit contains what you think it does. Documentation: Git: git diff Week 2 Scientific programming fundamentals git
Double and integer
R’s two numeric types: double for decimal numbers, the default, and integer for whole numbers, written with an L as in 42L. The difference rarely matters here, but whether a value is numeric at all does, and is.numeric() answers that. Documentation: R documentation: numeric vectors Week 3 Scientific programming fundamentals r data

E

Eight-step workflow
The fixed sequence every analysis in this course follows, from stating the estimand to reflecting on limitations. It is also the shape of the take-home exam, and each week deepens one or two of its steps, starting with the data summary. Week 4 Scientific programming fundamentals workflow
Error and warning
An error stops the code and nothing is computed, while a warning lets the code finish but flags something suspicious. Read an error in two parts, where it broke and what went wrong, before you change anything. See also: Render layers. Week 3 Scientific programming fundamentals r
Estimand
The quantity we want to learn about from data, such as the association between two variables, stated precisely before any analysis. Naming it first is what keeps the estimator and the estimate answerable to a question. Week 1 Orientation workflow interpretation
Estimate
The output of the estimator: the result we get back once the method has been applied to the data. Ideally it corresponds to the estimand, and checking how far it does is part of every analysis. Week 1 Orientation interpretation
Estimator
The procedure, our method, that turns data into an estimate of the estimand. The same estimand can be approached with different estimators, so the choice is one you have to justify. Week 1 Orientation workflow model
Excel workbook and sheet
An Excel file (.xlsx or .xls) is a workbook that can hold several sheets, each its own table. The readxl package, installed with the tidyverse but not loaded by it, lists the sheets and reads one at a time. Documentation: readxl Week 4 Scientific programming fundamentals data

F

Factor
R’s type for categories, a vector encoded with a fixed set of levels, such as autocracy, hybrid and democracy. Stored this way, categories can be ordered and counted, and the order of the levels controls how they appear in tables and plots. Documentation: R documentation: factors Week 3 Scientific programming fundamentals r data
File extension
The ending of a file name, such as .csv, .xlsx, .dta or .qmd, which tells you and your software what format the file is in. Each data format has its own reading function, so the extension tells you which one to reach for. Documentation: R for Data Science: data import Week 4 Scientific programming fundamentals data
Fresh R session
An R session with nothing in it yet, which is what Quarto starts for every render before running every cell from top to bottom. An object you created only in the console does not exist there, which is the usual reason a render fails with “object not found” while the console works. Week 3 Scientific programming fundamentals r quarto
Function and argument
A function is a named, reusable piece of code that takes inputs, its arguments, and returns an output, called as name(argument1, argument2). Arguments can be given by position or by name, and naming them makes code readable a month later. See also: Default argument value, Writing a function, Help page. Documentation: An Introduction to R: named arguments and defaults Week 3 Scientific programming fundamentals r

G

Geom
The kind of mark that represents the data in a plot, such as points, lines, bars or boxes, added as a geom_*() layer. Several geoms can be stacked on the same aesthetic mappings, for example points with a line through them. Documentation: ggplot2: layers Week 5 Scientific programming fundamentals data r
Git
A free and open-source distributed version control system that records the history of a project as a series of commits. It answers what changed, when, and why, and it lets you go back. Documentation: Pro Git: what is Git? Week 2 Scientific programming fundamentals git
GitHub
A cloud-based platform where you can store, share and work together with others on Git repositories. Git is the version control system on your computer, and GitHub is the service that hosts the remote copy, which is how homework is distributed and submitted in this course. Documentation: GitHub Docs: about GitHub and Git Week 2 Scientific programming fundamentals git
Grammar of graphics
The idea that every statistical figure is built from the same few parts: data, aesthetic mappings, geoms, scales, facets, labels and a theme (Wilkinson 2005; Wickham 2010). ggplot2 implements it, so a plot starts with ggplot() and grows one layer at a time with +. Documentation: ggplot2 Week 5 Scientific programming fundamentals data r
Graphical perception
How accurately readers decode the visual encodings of a chart: positions on a common axis and lengths best, angles, areas, depth and colour shades worst (Cleveland and McGill 1984). It is the reason pie charts and 3D charts mislead, and why most charts show values by position or length. Week 5 Scientific programming fundamentals data interpretation
Grouped summary
Reducing a table to summary statistics, such as a count or a mean, once for each group defined by the values of one or more columns. In dplyr, group_by() sets the groups without changing anything you can see, summarise() then returns one row per group, and count() is the shortcut for the number of rows per group. Documentation: dplyr: grouped data Week 4 Scientific programming fundamentals data r

H

Help page
The documentation every R function has, opened with ?mean or help(mean). Its sections say what the function does, which arguments it takes and their defaults (Usage and Arguments) and what it returns (Value), and the Examples at the bottom are usually the fastest way in. Documentation: An Introduction to R: getting help Week 3 Scientific programming fundamentals r
Histogram
A chart of one numeric variable that cuts its range into bins and draws a bar for the number of observations in each. The bin width is a choice that changes what the shape seems to say, so try several, and compare it with a smooth density curve. See also: Density plot, Skewed distribution. Week 5 Scientific programming fundamentals data probability

I

Indexing
Picking values out of a structure: [ ] by position or by condition, and $ by name, for data frames and lists. On a data frame [row, column] takes both (a blank means all), a negative position drops instead of keeps, and a logical vector keeps the elements where it is TRUE, which is filtering. Documentation: R documentation: extract or replace parts of an object Week 3 Scientific programming fundamentals r data
Inference
Learning from data: using what we have observed to say something about what we have not. Measuring two variables to learn about their association, or sampling people to learn about a population, are both inference. See also: Estimand, Signal and noise. Week 1 Orientation probability interpretation
Inline code
R code inside a sentence, written as a backtick, the letter r, a space, the code and a closing backtick, whose result replaces it in the rendered text. A number reported this way updates itself when the data or the code changes. Documentation: Quarto: inline code Week 3 Scientific programming fundamentals quarto r

J

Jitter
Small random shifts added to the position of points so that points on top of each other become visible, a remedy for overplotting. Because the shifts are random, set a seed with set.seed() so the figure looks the same on every render. Week 5 Scientific programming fundamentals data r
Join
Combining two tables by matching rows on a shared key, so the result has the columns of both. The four joins differ only in which rows survive when a key has no partner: a left join keeps every row of the first table, a right join every row of the second, an inner join only the matches, and a full join everything. Documentation: dplyr: mutating joins Week 4 Scientific programming fundamentals data

K

Key
The column, or columns, a join matches rows on, such as country, and when it has a different name in each table, join_by() says which columns belong together. A key matches text exactly, so one spelling difference silently produces NA: count the missing values after every join. Documentation: dplyr: join specifications Week 4 Scientific programming fundamentals data

L

Label
A unique name given to a figure, table, section or code cell, such as #fig-map, #tbl-results or #sec-intro, whose prefix says what kind of thing it is. A label is what a cross-reference points to. Week 2 Scientific programming fundamentals quarto
LaTeX
A high-quality typesetting system, the last layer of a PDF render, which turns the converted document into the PDF. Its errors usually come from a special character in your prose, such as %, &, $ or a stray backslash. Documentation: The LaTeX Project Week 4 Scientific programming fundamentals quarto
Layer
One component of a ggplot2 figure, such as a geom, a scale or a theme, stacked onto the plot with +. The native pipe only carries the data into ggplot(), and every step after that is a layer added with +. See also: Grammar of graphics. Week 5 Scientific programming fundamentals r data
Legend and direct labels
A legend is the key that decodes an aesthetic mapping, such as which colour stands for which continent. Direct labels write the name next to the data instead, which spares the reader from looking back and forth. See also: Annotation. Week 5 Scientific programming fundamentals data
Line plot
A chart that connects points in the order of the x axis, the natural choice for change over time. With several units, such as countries, each needs its own line through a grouping variable, and small multiples keep many lines readable. Week 5 Scientific programming fundamentals data
List
R’s flexible container, created with list(), which can hold anything, including other lists. You will rarely build one yourself, but every fitted model in this course comes back as one. Documentation: R documentation: lists Week 3 Scientific programming fundamentals r data
Literate programming
Writing code, the prose that explains it and its results in a single document, so the reasoning and the computation cannot drift apart. Quarto is the tool we use for it. Week 2 Scientific programming fundamentals workflow quarto
Local repository
The copy of a repository on your own computer, where you edit files and make commits. Your commits live only here until you push them to the remote. Week 2 Scientific programming fundamentals git
Log scale
An axis on which equal distances multiply the value instead of adding to it, so the steps from 1,000 to 10,000 and from 10,000 to 100,000 are equally long. It spreads out a right-skewed variable such as income, where an extra dollar matters more to the poor than to the rich. See also: Scale. Week 5 Scientific programming fundamentals data
Logical
R’s type for true or false, TRUE and FALSE, which every comparison returns. Logicals are the backbone of filtering, and the sum of a logical vector counts its TRUE values. Documentation: R documentation: logical vectors Week 3 Scientific programming fundamentals r data

M

Markdown
The plain-text formatting syntax used in the body of a .qmd: *italics*, **bold**, # for headings, > for a block quote, - for a list item, [text](url) for a link and | pipes for a table. Quarto uses Pandoc’s flavour of Markdown, which stays readable as source and still renders to a formatted document. Documentation: Quarto: Markdown basics Week 2 Scientific programming fundamentals quarto
Masking
What happens when a loaded package has a function with the same name as one already available, so the newer one wins. library(tidyverse) reports, for example, that dplyr::filter() masks stats::filter(), and the namespace operator :: picks one explicitly. Week 4 Scientific programming fundamentals r
Matrix
A two-dimensional arrangement of values of one type, in rows and columns, created with matrix() and written in bold uppercase as \(\mathbf{X}\). It is the workhorse of linear algebra, and of every regression under the hood. Documentation: R documentation: matrices Week 3 Scientific programming fundamentals r data
Mean and standard deviation
The mean \(\mu\) is the centre of a distribution, and moving it slides a normal curve left or right. The standard deviation \(\sigma\) is its spread, and raising it makes the curve wider and flatter. Week 1 Orientation probability data
Median
The middle value of a set of numbers once they are sorted, so half the values lie below it and half above. Unlike the mean, it barely moves when a few values are extreme, which makes it the better summary of skewed data such as income. Week 4 Scientific programming fundamentals probability data
Missing values in calculations
Most summary functions, such as mean() or sum(), return NA if any value is missing, because the true answer is then unknown. Their argument na.rm = TRUE removes the missing values first, which is a decision about your data worth stating in the text. Documentation: R documentation: mean Week 3 Scientific programming fundamentals r data

N

NA
R’s marker for a missing value, “not available”. It appears when a value was never recorded, when a conversion fails and when a join finds no match, so always check how many you have. See also: Missing values in calculations. Documentation: R documentation: NA Week 3 Scientific programming fundamentals r data
Namespace (::)
Calling a function by naming the package it lives in, written package::function(), as in readxl::read_excel(). It makes the source clear, needs no library() for a one-off call, and settles which function you mean when two packages share a name. See also: Masking. Documentation: R documentation: double colon Week 4 Scientific programming fundamentals r
NaN
R’s value for “not a number”, the result of a calculation with no defined answer, such as 0 / 0 or sqrt(-1). It usually comes with a warning, and R also counts it as a missing value. Documentation: R documentation: finite, infinite and NaN numbers Week 3 Scientific programming fundamentals r data
Native pipe
The |> operator, which passes the value on its left into the function call on its right as the first argument, so a sequence of steps reads left to right, as “and then”. This course uses |> throughout and not the older %>% from the magrittr package. See also: Pipeline. Documentation: R documentation: forward pipe operator Week 3 Scientific programming fundamentals r
Nested function call
A function call inside another, such as round(mean(x), digits = 1), which R evaluates from the inside out. Deep nesting is hard to read, which is what the native pipe is for. Week 3 Scientific programming fundamentals r
Normal distribution
The symmetric bell-shaped distribution, written \(\mathcal{N}(\mu, \sigma)\) in this course. It has exactly two knobs, the mean and the standard deviation, and no other shape is available. See also: Rule of 68 and 95 percent, Standard normal distribution. Week 1 Orientation probability

O

Object
A named container holding information, with a name, a value and a type. In R, everything that exists is an object, including functions and fitted models. Documentation: R Language Definition: objects Week 3 Scientific programming fundamentals r
Observation
One unit of what was measured, such as one country in one year. In tidy data each observation has its own row. Week 3 Scientific programming fundamentals data
One sentence per line
Writing prose in a .qmd with each sentence on its own source line. The rendered document looks the same, but the diff can now show a change sentence by sentence. Week 2 Scientific programming fundamentals quarto git
Open-source licence
A licence that allows anyone to use, copy, change and share a piece of work under stated conditions, such as keeping the copyright notice, the MIT License being a short and common example. Adding it as license.md to a homework repo is how you opt in to AI feedback. Documentation: GitHub Docs: licensing a repository Week 2 Scientific programming fundamentals workflow git
Opt-in AI feedback
The only individual feedback on homework: if your submission repo contains an open-source licence as license.md, an AI compares your work with the sample solution and adds a FEEDBACK.pdf to your repo. Without that file your submission is not processed at all. Week 2 Scientific programming fundamentals workflow
Output format
The kind of document a render produces, such as HTML, PDF or Word, set with format: in the YAML header. The source stays the same whatever the format: one source, several outputs. Documentation: Quarto: all formats Week 2 Scientific programming fundamentals quarto
Overplotting
Marks drawn on top of each other, so a plot hides how many observations sit in one place. Transparency, small points, jitter or small multiples make the hidden density visible again. Week 5 Scientific programming fundamentals data

P

Package
A bundle of R functions, their documentation and sometimes data, that someone wrote and shared, whose contents become available only once it is loaded. Install it once with install.packages() in the console, and load it every session with library() at the top of the document. See also: CRAN, Namespace (::). Documentation: An Introduction to R: packages Week 3 Scientific programming fundamentals r
Pandoc
A universal document converter, which Quarto runs after the code cells have executed to turn Markdown into HTML, Word or LaTeX. An error from the YAML header surfaces at this layer, with a line and column number. Documentation: Pandoc Week 4 Scientific programming fundamentals quarto
Pipeline
A sequence of steps chained with the native pipe, each taking the previous result, from reading a file to a finished table. Pipelines are powerful, so build them one step at a time and check the result at every step. Documentation: R for Data Science: data transformation Week 4 Scientific programming fundamentals r workflow
Positron
A free data science environment, an IDE (integrated development environment), for R and Python, and the editor this course works in. By default the editor sits above the console and the terminal, with the Variables and Plots panes on the right and views such as the Explorer and Source Control in the Activity Bar. Documentation: Positron: layout Week 2 Scientific programming fundamentals workflow
Probability density
The height of the curve of a continuous probability distribution. The density itself is not a probability: the area under the curve between two values is. Week 1 Orientation probability
Probability distribution
A description of how plausible each possible value of a quantity is. For a continuous quantity it is drawn as a density curve, and the area under the curve between two values is the probability of landing between them. Week 1 Orientation probability
Project root
The top folder of a project, the fixed point every other path is expressed relative to. The here package builds every path from it, as in here("data", "file.csv"), which is what makes a project run on a machine other than yours. Documentation: here package Week 4 Scientific programming fundamentals workflow r
Push and pull
Sending your local commits to the remote (push), and bringing commits from it into your local repository (pull). The Sync button in Positron does both. Documentation: Git: git push Week 2 Scientific programming fundamentals git

Q

Quarto
An open-source scientific and technical publishing system that turns a .qmd file of Markdown and executable code cells into HTML, PDF, Word, slides and more. Everything in this course, including this page, is a Quarto document. Documentation: Quarto: Hello, Quarto (Positron) Week 2 Scientific programming fundamentals quarto

R

Redundant encoding
Showing the same variable through two visual properties at once, such as colour and point shape, so that colour is never the only cue. It keeps a figure readable for colourblind readers and in a black and white print. Week 5 Scientific programming fundamentals data
Remote
A version of your repository hosted on the internet, normally on GitHub, that you push to and pull from. The remote is what makes the work shared rather than local. Documentation: Pro Git: working with remotes Week 2 Scientific programming fundamentals git
Render
Quarto’s term for taking a source .qmd, running its code cells and producing a new output document, from the Preview button in Positron or with quarto render in the terminal. A submission that does not render is not a submission, because nobody else can reproduce it. See also: Fresh R session, Render layers. Documentation: Quarto: rendering Week 2 Scientific programming fundamentals quarto workflow
Render layers
The programs a PDF render passes through in turn: R runs the code cells, Pandoc converts the Markdown, and LaTeX typesets the PDF. An error message shows which layer failed, and only the first error counts, so fix that one and render again. Week 4 Scientific programming fundamentals quarto
Repository
A project under version control: its files together with the full history of every change, usually shortened to “repo”. You get one either by initialising a folder as a new repository, which is what git init and Positron’s Source Control pane do, or by cloning an existing one. See also: Local repository, Remote. Documentation: Pro Git: getting a Git repository Week 2 Scientific programming fundamentals git
Reproducible research
Research whose results can be regenerated from the raw data and the code alone, by someone else, on another machine. The practical test is whether one render rebuilds every number and figure in the output. Week 2 Scientific programming fundamentals workflow
Reshaping
Changing the layout of a table without changing its information, in the tidyverse by pivoting: pivot_longer() turns column names into values of a new variable, and pivot_wider() turns values back into column names. Rule of 68 and 95 percent
For any normal distribution, about 68 percent of the probability lies within one standard deviation of the mean, and about 95 percent within two. It is why \(\mathcal{N}(5, 2)\) reads as “5, plus or minus about 4”. Week 1 Orientation probability

Scientific notation

Signal and noise
Signal is the real pattern in the world that we want to learn about, and noise is random variation from measurement or data collection. Telling the two apart, and saying how certain we can be that we have, is the fundamental task of learning from data. Week 1 Orientation probability interpretation

Skewed distribution
A distribution with a long tail on one side, such as income: many small values and a few very large ones make it right-skewed. In a skewed variable the mean is pulled towards the tail, so the median or a log scale often describes it better. Week 5 Scientific programming fundamentals probability data

Standard normal distribution
The normal distribution with mean 0 and standard deviation 1, \(\mathcal{N}(0, 1)\). Every other normal distribution is that same shape, shifted and stretched, which is what standardising undoes. Week 1 Orientation probability
Standardising
Subtracting the mean and dividing by the standard deviation, \(z_i = (x_i - \mu) / \sigma\), which turns any normal variable into a standard normal one. A value of \(z_i = 2\) then means the same thing everywhere: two standard deviations above the mean. Week 1 Orientation probability data

Vectorisation
Applying an operation to every element of a vector at once, without writing a loop: c(84, 68) * 1000000 multiplies both values. Most R operators and functions are vectorised, which is why a function written for one value usually works on a whole column too. A tidyverse function named for what it does to a table, such as dplyr’s filter() (keep rows), select() (keep columns), mutate() (create or change columns) and arrange() (sort rows).
